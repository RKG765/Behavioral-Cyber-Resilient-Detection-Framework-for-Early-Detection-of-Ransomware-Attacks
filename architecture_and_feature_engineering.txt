PART 1: COMPREHENSIVE END-TO-END SYSTEM ARCHITECTURE
====================================================================================================

1.1 THE FUNDAMENTAL EDR DILEMMA:
Modern Endpoint Detection and Response systems are caught in a trilemma:
1. Cloud-Only Latency Bottleneck: Streaming raw telemetry to the cloud creates a 300ms to 2,000ms delay.
   Modern ransomware strains (LockBit 3.0, BlackCat) use multi-threaded I/O completion ports to encrypt files
   in under 100 microseconds per file. By the time the cloud returns a verdict, the master file table is encrypted.
   Furthermore, streaming billions of daily events creates unsustainable cloud network bandwidth and ingestion bills.
2. Heavy Edge Model Failure: Deploying deep neural networks (Transformers, heavy CNNs) to the endpoint
   drains >20% CPU and >500 MB RAM, exhausting laptop batteries and causing workstation freezes.
3. Rule-Based Alert Fatigue: Static signatures fail on polymorphic malware. Rule heuristics trigger >95%
   false alarms, causing analysts to ignore legitimate zero-day intrusions.

1.2 ARCHITECTURAL OVERVIEW & CORE INNOVATIONS:
Our solution decouples local gatekeeping from deep contextual reasoning using an Asymmetric Two-Tier architecture:
- Tier 1: Local edge gatekeeper. Ultra-lightweight behavioral MLP exported to ONNX (<1.8ms latency, 10.8 KB size, <150MB RSS).
- Tier 2: Cloud heavy brain. Deep Behavioral ResNet with BatchNorm1d hosted on FastAPI with GPU/multi-core compute.
- Asymmetric Gating: 90% to 95% of processes are resolved locally at the edge in <2ms with ZERO cloud egress.
  Only ambiguous "Grey Zone" processes (0.10 < Score < 0.90) are escalated to Cloud Tier 2, saving 95% of bandwidth.

1.3 KERNEL INTERCEPTION & THREAD POOL INGESTION:
When a binary executes on Windows, interception occurs via WMI (Win32_ProcessStartTrace) and ETW kernel callbacks.
To ensure non-blocking operation, events are dispatched to a multi-threaded worker pool. The worker extracts:
- Target Process ID (PID)
- Process Name & Absolute Image Path
- Parent PID & Process Hierarchy
- Command-line Arguments

1.4 LEVEL 1 ZERO-COST FAST-PATH GATING:
Before any machine learning model is invoked, binaries pass through two fast-path layers:
- L1A (WinTrust Authenticode): Calls the Win32 WinVerifyTrust API (wintrust.dll) with WINTRUST_ACTION_GENERIC_VERIFY_V2.
  Validates that the digital signature chains to trusted Microsoft or approved vendor root CAs (Google, Brave, Adobe).
  Valid signatures are cached in an in-memory Least-Recently-Used (LRU) table keyed by (filepath, st_mtime, st_size).
  Subsequent launches incur 0.0ms computational overhead. If an attacker modifies the binary on disk, st_mtime or
  st_size changes instantly, invalidating the cache.
- L1B (SQLite Whitelist Cache): Unsigned internal enterprise software is matched against whitelist.db using indexed
  SHA-256 hashes in < 0.2ms.
Result: Over 85% of standard workstation binaries bypass ML entirely with zero CPU overhead.

1.5 DYNAMIC 30-SECOND BEHAVIORAL WINDOW:
If a binary is unknown or unsigned, it enters the BehaviorMonitor. The agent tracks the process for up to a 30-second
sliding window via circular ring buffers, capturing syscalls, file writes, registry modifications, and network connections.
The 30-second window is an upper bound: if anomalous behavior occurs early (e.g. DLL injection or network bursts),
the score crosses thresholds immediately and terminates the process without waiting for the full 30 seconds.

1.6 TIER 1 EDGE GATEKEEPER (ONNX MLP ARCHITECTURE):
- Architecture: Linear(99 -> 128) -> BatchNorm1d -> ReLU -> Dropout(0.3) -> Linear(128 -> 64) -> BatchNorm1d -> ReLU -> Dropout(0.3) -> Linear(64 -> 1) -> Sigmoid.
- Compiled Artifact: tier1_behavioral.onnx (10.8 KB).
- Hardware Telemetry: Runs via ONNX Runtime CPU Execution Provider. Single-core latency is < 1.8ms (1.4ms mean),
  consuming 0.0% idle CPU and maintaining a 138.4 MB resident memory (RSS) footprint (budget < 150 MB).

1.7 THE ASYMMETRIC HANDSHAKE (GREY-ZONE PROTOCOL):
Tier 1 evaluates the suspicion score S_T1:
- S_T1 <= 0.10 [Clear Benign]: Instant allow. 0.00% False Negative Rate. Zero network cost.
- S_T1 >= 0.90 [Clear Malware]: 100% precision threshold. Agent calls Win32 TerminateProcess API in < 2ms,
  killing ransomware before sockets open or encryption begins.
- 0.10 < S_T1 < 0.90 [Grey Zone]: Ambiguous process where edge inference has residual epistemic uncertainty.
  Dispatched asynchronously via HTTP POST to Cloud Tier 2 (server.py:8000).

1.8 TIER 2 CLOUD HEAVY BRAIN (FASTAPI & RESNET):
- Architecture: Projection Linear(99 -> 64) -> BatchNorm1d -> ReLU -> Two Residual Blocks (Linear(64->64) + BN + ReLU + Linear(64->64) + BN + Identity Skip) -> Linear(64 -> 1) -> Sigmoid.
- Loss Function: Focal Loss (gamma=2.0, alpha=0.25) to focus gradient updates on hard, borderline samples.
- Cloud Service: FastAPI asynchronous microservice listening on port 8000 (/score and /health endpoints).

1.9 OPERATING THRESHOLD DERIVATION (THETA = 0.6546):
The operating threshold was derived from empirical ROC curve optimization to strictly bound the False Positive
Rate (FPR) below 1.0%:
- S_T2 > 0.6546: Kill directive returned to agent; process terminated and binary quarantined.
- S_T2 <= 0.6546: Allowed as legitimate enterprise tool (e.g. administrative build script).
Result: 99.26% Precision ensures that business operations are never disrupted by false alarms.

1.10 EXPLAINABLE AI (XAI) VIA INTEGRATED GRADIENTS:
For every KILL verdict, Tier 2 calculates Integrated Gradients across the 99 input features:
  Attr_i(x) = (x_i - x'_i) * integral_0^1 (grad_i S_T2(x' + alpha*(x - x'))) d_alpha
Attributes top suspicious features (e.g. Base64 command +0.312, Temp execution +0.245, DLL burst +0.187)
and streams human-readable explanations directly to the SOC console.

1.11 INCIDENT RESPONSE COCKPIT:
Security analysts have one-click containment actions:
- Quarantine Process: Suspends PID, severs active threads, and moves binary to an encrypted vault.
- Blacklist C2 IP: Automatically creates an outbound Windows Firewall rule blocking the command-and-control IP.
- Sever Host Network: Severely isolates workstation from local subnet while keeping the EDR management tunnel open.

1.12 ZERO-REFRESH REAL-TIME SOC TELEMETRY PIPELINE:
Two complementary zero-refresh user interfaces were built:
1. Streamlit SOC Dashboard (edr_soc_dashboard.py on port 8501):
   Uses Streamlit 1.56.0's native @st.fragment(run_every="1s"). Isolates telemetry execution so gauges,
   KPI cards, and triage tables update live without resetting user filters, inputs, or reloading the browser.
2. Modern Web Application (web_app.py on port 5050):
   FastAPI WebSocket server (/ws) pushing JSON telemetry packets every 1.0 second. HTML5 Canvas circular gauges
   render smooth animation loops without DOM re-renders.

2.1 PHILOSOPHY: BEHAVIORAL INVARIANCE VS. TOKEN BRITTLE-NESS:
Legacy EDRs that train models on sequential EventID tokens (e.g. [1, 7, 3, 11]) suffer from trivial evasion:
an attacker can interleave dummy benign system calls (reading registry keys or listing directories) to break
the sequential pattern.
Our 99 features capture behavioral structural invariants—event ratios, execution velocity, burstiness,
and contextual paths—that cannot be concealed by inserting dummy events.

2.2 FEATURE NORMALIZATION PROTOCOL:
Features are float32 normalized:
- Frequency counts: Scaled by total event window count (relative proportions in [0.0, 1.0]).
- Velocity features: Computed as delta_events / delta_time (events per millisecond).
- Categorical / Boolean indicators: One-hot or binary encoded (0.0 or 1.0).

4.1 PROBLEM 1: WINTRUST OS API THREAD DEADLOCKS
- Symptom: When querying Windows Authenticode via WinVerifyTrust, the API would occasionally deadlock if an
  installer locked the target binary with exclusive read/write access, or if network connectivity for CRL
  checking stalled, hanging the agent thread.
- Applied Solution: We isolated Authenticode verification into a non-blocking worker thread pool with a strict
  1.5-second timeout watchdog. If the API does not return within 1.5 seconds, the watchdog aborts the query,
  classifies the binary as untrusted, and routes it into the dynamic behavioral analysis pipeline without freezing the agent.

4.2 PROBLEM 2: PROCESSGUID DATA LEAKAGE TRAP
- Symptom: Initial experiments using standard random train/test splits showed an unrealistic 99.9% accuracy.
  When tested against new process trees, the accuracy collapsed.
- Root Cause: In Windows, child processes share executable paths and parent IDs with their parent. A random split
  placed the parent process in the training set and its child process in the test set. The model memorized the path
  rather than learning generalizable behavior.
- Applied Solution: We indexed every telemetry trace by its globally unique Sysmon ProcessGuid and enforced strict
  5-Seed GroupKFold cross-validation. An entire process family is kept exclusively in Train OR Validation.
  This guaranteed that our 97.03% accuracy represents true out-of-sample generalization against novel malware.

4.3 PROBLEM 3: CATASTROPHIC COLLAPSE ON FOLD 5 (SEED 2024)
- Symptom: During Tier 2 training on Seed 2024 (Fold 5), validation AUC collapsed to 0.5000 (random guessing),
  with the network predicting a constant 0.0 logit.
- Root-Cause Analysis:
  1. LayerNorm on Tabular Features: LayerNorm normalizes across the feature dimension within a single sample.
     In NLP, word embeddings share a common latent dimension. But on tabular EDR features, Feature 6 is an
     ImageLoad count (e.g. 48) while Feature 27 is a binary flag (0 or 1). Normalizing across heterogeneous feature
     scales destroyed their individual physical semantics.
  2. Over-Parameterization: A projection dimension of 128 created over 50,000 parameters for only 1,470 samples,
     leading to gradient instability and saddle point traps.
- Applied Solution:
  1. Swapped LayerNorm to BatchNorm1d across all residual blocks. BatchNorm1d normalizes each feature independently
     across the batch, preserving individual feature semantics.
  2. Reduced the projection dimension from 128 to 64, cutting parameters from 50K to ~18K.
- Verification: Retraining across all 5 seeds (25 folds) confirmed 100% convergence, with Fold 5 AUC jumping
  from 0.5000 to over 0.9950.
